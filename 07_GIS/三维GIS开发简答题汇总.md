## 一、实习一：上机实习

### 1.1 散点可视化

**问题**：讨论并回答，这提示了一种什么样的工作流程？

**答案**：  
这提示了一种 **数据处理与可视化分离但协同工作** 的流程。具体而言：

1. **数据预处理与格式转换**：利用 Python（Pandas）读取原始数据（如 CSV），提取所需变量（x/y/z/v），并构建为 VTK 所支持的几何结构（顶点、单元、属性），最终输出为标准的 VTK 矢量文件。这一步骤实现了从原始数据到可视化数据格式的自动化转换。
2. **交互式可视化与后处理**：将生成的 VTK 文件导入 ParaView 这类专业可视化软件中，利用其丰富的交互功能（如调整颜色映射、渲染样式、添加标注等）进行深入分析和视觉呈现。用户可以根据需要手动调整视觉样式，甚至通过脚本（如 Python trace）复现这些效果，实现可重复的可视化流程。

**优势**：
- **分工明确**：Python 处理数据，ParaView 负责可视化。
- **可重复性与自动化**：脚本生成 VTK，数据更新后快速重建场景。
- **跨平台与协作**：VTK 是通用科学可视化格式，便于交换数据。

### 1.2 多边形与三角化

**问题**：三种多边形（原始多边形、vtkTriangleFilter 三角化、vtkDelaunay2D 三角化）有什么区别？

**答案**：

| 特征 | vtkTriangleFilter | vtkDelaunay2D |
|------|-------------------|---------------|
| 算法 | 简单耳切法（Ear Clipping） | 基于 Delaunay 准则（空圆性质） |
| 三角形质量 | 可能较差（狭长、瘦小） | 通常较好（最大化最小角） |
| 边界保持 | 较好 | 可能改变边界形状或添加点 |
| 计算速度 | 快 | 相对较慢 |
| 空洞处理 | 可能填充内部的洞 | 需要额外处理 |
| 点集变化 | 不变 | 可能添加额外点 |

**原始多边形**：由一系列有序顶点构成的封闭多边形，可以是任意形状，边数不限，显示为红色线框，只看到边界轮廓。

**为什么图形学工业需要三角化？**  
显卡硬件只支持三角形渲染（光栅化），多边形必须分解为三角形才能被 GPU 正确绘制。

### 1.3 长度计算（测地距离 vs 欧氏距离）

**问题**：测地距离（表面距离）与欧氏距离（直线距离）的比值（如平均值）包含什么地理学意义？

**定义**：  
比值 = **测地距离（表面距离） / 欧氏距离（直线距离）**

由于地表是起伏的，沿地表行走的最短路径（测地距离）一定不小于穿过地表的直线距离（欧氏距离），因此 **比值 ≥ 1 恒成立**（理论上等于1仅当平面；小于1不可能出现，除非数据误差或网格边界效应）。

**地理学意义**：

| 比值 | 含义 | 说明 |
|------|------|------|
| **> 1** | 表面距离 > 直线距离 | 地形起伏导致实际路径变长。比值越大，地形越复杂、崎岖度越高（山地 > 丘陵 > 平原）。 |
| **= 1** | 表面距离 = 直线距离 | 地形完全平坦（如平原、台地）。 |
| **< 1** | **不可能发生** | 测地距离是曲面上最短路径，不可能小于直线穿过的距离。若计算出现 <1，检查数据或算法错误。 |

**平均比值的地理学意义**：
- **整体地形复杂度指标**：例如平均比值 1.2 表示“由于地形起伏，地表实际行走距离比直线距离平均长出 20%”。
- **与地形因子的关系**：平均比值与坡度、地表粗糙度、地形起伏度正相关。
- **应用价值**：可达性分析（山地救援、徒步路线规划）、生态廊道构建（动物迁徙成本）、水文分析（径流路径长度）、地貌自动分类等。

**常见易错点**：  
- 不要将分子分母颠倒。若误用 **欧氏距离 / 测地距离**，则比值 ≤ 1，且地形越复杂比值越小，这与物理直觉相反，也非本实验定义。  
- 本实验中代码明确为 `ratio = surface_distances / euclidean_distances`，因此比值 ≥ 1。

### 1.4 面积计算（曲面面积 vs 平面面积）

**问题**：三维表面面积与平面面积比值的地理学含义是什么？

**答案**：
- 比值 ≥ 1，表示实际地表面积是投影面积的倍数（恒≥1）。
- 比值越大，地形越崎岖（山地 > 丘陵 > 平原）。
- **应用**：水土流失评估、生态容量估算、道路选线等需使用真实面积而非投影面积。

**示例**：本区地形平坦（比值≈1） / 轻微起伏 / 中等起伏 / 复杂起伏。

**简答题 3**：对于 AI 加工地理信息数据，我们特别关心的两点是什么？

**答案**：
- **几何精度与拓扑一致性**：AI 生成或处理的数据可能引入位置偏差、自相交等拓扑错误，需验证几何是否符合实际地理空间规则。

4. **业务应用与智慧赋能**：基于三维底座开发城市规划“一键监督”、土地招商“一图统揽”、城市安全监测（内涝模拟、火灾应急）、智慧交通（车路协同）、历史文化保护等专题应用。

| 量表类型 | 描述 | 数学特性 | 可视化示例 | 关联的几何数据结构 |
|----------|------|----------|-------------|-------------------|

**题目 3**：读取地形三角网，随机选取种子点进行 Voronoi 聚类，如果距离选择直线欧氏距离与测地距离，可视化结果有何不同？

**答案**：
- **欧氏距离（直线距离）**：无视地形起伏，聚类边界在三维空间中是直的。一个点虽然在平面投影上离某个种子点很近，但实际可能隔着一座山，根据欧氏距离仍被归为同一类。结果看起来像是用平直的平面切割地形。
- **测地距离（表面距离）**：沿着地形表面计算“走过去有多远”。聚类边界严格遵循地形的“分水岭”或山脊线。一个山谷两侧的点，虽然空间直线距离很近，但由于被山脊阻隔，测地距离很远，因此会被划分到不同的 Voronoi 单元中。结果显示出沿着地形起伏的自然划分边界，更具地理意义。

### 第四次作业

**问题**：简述纹理映射的数学原理。

**答案**：  
纹理映射的本质是建立三维模型顶点 \((X, Y, Z)\) 与二维纹理像素 \((u, v)\) 之间的坐标映射关系，可看作三维世界到二维照片的投影变换。主要包括三大坐标系变换：

1. **世界坐标系 → 相机坐标系**：通过相机外参（$旋转矩阵 R 和平移向量 t$）将点变换到相机视角下：
   $$
   \begin{bmatrix} X_c \\ Y_c \\ Z_c \end{bmatrix} = R \begin{bmatrix} X \\ Y \\ Z \end{bmatrix} + t
   $$

2. **相机坐标系 → 图像坐标系**：利用相机内参（$焦距 f_x, f_y、光心 c_x, c_y$）进行透视投影：
   $$
   u = f_x \frac{X_c}{Z_c} + c_x,\quad v = f_y \frac{Y_c}{Z_c} + c_y
   $$

3. **整体变换矩阵**：合并为齐次坐标下的单一公式：
   $$
   s \begin{bmatrix} u \\ v \\ 1 \end{bmatrix} = K \begin{bmatrix} R & t \end{bmatrix} \begin{bmatrix} X \\ Y \\ Z \\ 1 \end{bmatrix}
   $$
   其中 $K$ 为相机内参矩阵，$\begin{bmatrix} R & t \end{bmatrix}$ 为相机外参矩阵，$s$ 为缩放因子。

### 第五次作业

**问题**：研究 `IntersectWithLine` 函数的功能与参数，给出正确的调用方式并验证结果。

**答案**：

- **功能**：求线段与网格的第一个交点。
- **函数原型（VTK C++ 风格，Python 中类似）**：
  ```cpp
  int IntersectWithLine(double p1[3], double p2[3], double tol,
                        double &t, double x[3], double pcoords[3],
                        int &subId, vtkIdType &cellId)
  ```
- **参数解释**：
  - `p1, p2`：线段端点坐标（长度为 3 的数组）。
  - `tol`：容差（通常取 `1e-6`）。
  - `t`：交点在线段上的参数（0~1），引用传递。
  - `x`：交点的世界坐标（输出）。
  - `pcoords`：交点所在单元的参数坐标（输出）。
  - `subId`：子单元 ID（输出）。
  - `cellId`：相交的单元 ID（输出）。
- **返回值**：1 表示有交点，0 表示无交点。
- **调用方式示例**（Python）：
  ```python
  import vtk, numpy as np
  r = vtk.vtkPolyDataReader(); r.SetFileName("mesh.vtk"); r.Update()
  pd = r.GetOutput()
  loc = vtk.vtkCellLocator(); loc.SetDataSet(pd); loc.BuildLocator()
  p1, p2 = [0,0,10], [0,0,-10]
  t = vtk.reference(0.0); x = np.zeros(3); pcoords = np.zeros(3)
  sub = vtk.reference(0); cell = vtk.reference(0)
  hit = loc.IntersectWithLine(p1, p2, 1e-6, t, x, pcoords, sub, cell)
  if hit:
      print(f"交点坐标: {x}, 单元ID: {cell}")
  ```

### 第六次作业

**题目 1**：点云的结构特点有什么？加工算法需要针对这些特点进行哪些设计？

**答案**（表格形式）：

| 特点            | 说明                           | 对算法设计的影响                                        |
| ------------- | ---------------------------- | ----------------------------------------------- |
| **无序性**       | 点的存储顺序无几何意义，改变排列不影响形状        | 不能依赖索引顺序；需用 KD-tree、八叉树等空间数据结构进行邻域搜索            |
| **稀疏性与非均匀密度** | 点只分布在物体表面，且扫描角度、遮挡导致局部密度差异大  | 需要自适应邻域半径的搜索策略（半径搜索或 k 近邻）；下采样、上采样或法向估计时需考虑密度变化 |
| **非结构化**      | 无规则的拓扑连接信息，不同于网格的顶点-面片关系     | 特征提取（法向量、曲率）需借助主成分分析（PCA）；表面重建需额外构建网格或隐式场       |
| **海量性与高维属性**  | 单次扫描可达百万至亿级点，可能附带颜色、强度、法向等属性 | 需考虑内存效率与计算复杂度，常用分块处理、流式读取、GPU 加速、体素降采样等策略       |
| **噪声与离群点**    | 测量误差、运动物体或多次反射会产生噪点          | 需设计滤波预处理步骤（如半径滤波、统计滤波）以保证后续处理稳定性                |

**题目 2**：两幅影像要进行布尔运算，需要满足什么条件？

**答案**：
两幅影像（栅格图像）要进行像素级的布尔运算（如与、或、非、异或），需满足以下四个条件：

1. **相同的空间参考**：两影像必须具有完全相同的地理坐标系或投影坐标系，否则像素在空间位置上不匹配。
2. **相同的地理范围与起始坐标**：左上角（或左下角）的坐标必须一致，确保像素格网完全对齐。
3. **相同的分辨率（像元大小）**：每个像素代表的地面尺寸必须相同，否则同一地物对应不同数量的像素。
4. **相同的行列数（尺寸）**：宽度（列数）和高度（行数）须一致，以保证像素一一对应。

若上述任一条件不满足，需先进行影像配准、重采样或裁剪/镶嵌，使两幅影像在空间上严格对齐后再执行布尔运算。

**题目 3**（包含两个子问题）：

- **(1) `img.GetCell(i).GetBounds()`，单元中心点坐标是什么？**  
  `GetBounds()` 返回一个包含 6 个浮点数的元组或列表：`(xmin, xmax, ymin, ymax, zmin, zmax)`。单元中心点坐标计算公式为：
  ```python
  center_x = (xmin + xmax) / 2.0
  center_y = (ymin + ymax) / 2.0
  center_z = (zmin + zmax) / 2.0
  ```

- **(2) `vtkCellDataToPointData()`，转换单元属性至点属性，它的作用是什么？**  
  `vtkCellDataToPointData` 是 VTK 中的一个滤波器，作用是将存储在单元格（Cells）上的属性数据转换为存储在点（Points）上的属性数据。**工作原理**：对于每个点，找出所有共享该点的单元格，将这些单元格上对应属性的值进行平均（默认）或其他统计操作（如最大值、最小值），然后将计算结果作为该点的属性值。**在课堂练习中的必要性**：修改后的代码中将距离值赋予单元格，但后续的 `vtkContourFilter` 等值面提取需要点属性来插值确定等值面位置。若不进行转换，滤波器无法获取点上的标量值，将导致运行错误或无法生成等值面。
